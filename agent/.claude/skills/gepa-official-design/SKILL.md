# GEPA 공문서 작성 규격

참고 원문 분석: `reference/design-system.md` (두문·결문 셀 지도, paraPr 27/28/29, 스타일 수치).

## 자동 생성되는 부분 (front-matter로만 제어)
두문 표(기관명·수신·경유·제목), 결문 표(발신명의·결재란·협조자·시행·접수·주소·연락처·공개구분)는
front-matter에서 자동 생성된다. 본문에는 쓰지 않는다.

```yaml
---
family: official
수신유형: 수신자참조          # 내부결재 | 수신자 | 수신자참조
수신자: [경영지원팀장, 마케팅팀장]  # 수신유형=수신자참조 일 때
# 수신: 경영기획실장(경영지원팀장)   # 수신유형=수신자 일 때
경유: ""                     # 있을 때만
제목: 2026년 사업 추진 현황 제출 요청
발신명의: ""                 # 비우면 처리과가 속한 실·단 이름 + "장"으로 자동 채움(전결 등 명시할 때만 적는다)
처리과: 전략기획팀           # 시행 칸에 "전략기획팀-" 로 찍힌다 — 일련번호는 절대 쓰지 않는다
공개구분: 공개               # 공개 | 부분공개 | 비공개
결재라인: []                 # 비우면 lib/org.ts 의 approvalLineFor(처리과). 전결은 결재라인을 짧게 적어 표현한다
협조자: []
연락처: { 전화: 054-470-8527, 이메일: nancy.kwon@gepa.kr }
붙임: ["(양식) 2026년 사업 추진 현황_팀명 1부."]   # 없으면 빈 배열 — 이때는 본문 마지막 줄에 직접 "  끝."을 쓴다
---
```

**`시행번호`·`접수번호` 키는 스키마에 없다.** 전자결재 시스템이 기안 후에 채번하므로 절대 만들지
않는다 — 실제 공문서에 임의의 일련번호를 적으면 중대한 오류다.

## 본문
`#` 제목 문법은 쓰지 않는다 — 공문서 본문은 항목(`1.` `가.` `1)` `가)` `(1)` `(가)` `①` `㉮`)으로만
구성된다(편람 §3). 항목이 하나뿐이면 기호를 붙이지 않는다. 필요하면 `□`/`ㅇ`/`-`/`·` 특수기호도
쓸 수 있다(GOV 2타 사다리, `reference/gov-manual.md` §3).

```
경영평가 상시대응체계 구축 및 원활한 사업 관리를 위해 2026년 사업 추진 현황을 매월 점검하고자
하오니 각 팀에서는 다음과 같이 자료를 제출하여 주시기 바랍니다.
1. 작성대상: 2026년 각 팀에서 운영하고 있는 전체 사업
2. 작성기준: 전월 말일 기준 사업별 예산 집행액 및 지원 현황
3. 제출기한: 매월 5일까지
```

첫 본문 문단은 두문 표와 같은 문단에 들어간다(작성기가 처리한다 — 작성자는 신경 쓰지 않는다).

## 붙임과 `끝.`
붙임물이 있으면 front-matter의 `붙임:` 목록에 명칭·수량을 적는다(예: `"○○계획서 1부."`) — 본문에
직접 타이핑하지 않는다. 작성기가 항목이 하나면 번호 없이, 둘 이상이면 `1.`/`2.`로 매기고 마지막
항목 뒤에 `  끝.`을 자동으로 붙인다. **붙임이 없으면** 본문 마지막 문단 끝에 두 타 띄우고 직접
`끝.`을 쓴다(시행규칙 제4조제4·5항). `govLint`가 둘 다 검사한다.

## 문체
- 개조식이 아니라 문장체(`~하시기 바랍니다`, `~제출하여 주시기 바랍니다`) — 공고문·계획서와 다르다.
- 고압적 표현(`~할 것`, `~바람`)은 쓰지 않는다.
- 발신명의는 사람 이름이 아니라 직위(예: `경영기획실장`)를 쓴다.

## 행정업무운영 편람 준수
`reference/gov-manual.md` §2–§4를 따른다: 날짜 `2026. 7. 14.`(일 뒤 마침표·0 생략), 시간 `15:20`,
금액 한글 병기, 쌍점 앞 붙임, 물결표 앞뒤 붙임(`7. 1.~7. 15.`), 항목 하나에 기호 금지, 한자·외국어
괄호 병기, 순화어. `reference/design-system.md` §6에 이 문서가 적용하는 규정과 구현 지점을 표로
정리해 두었다.
