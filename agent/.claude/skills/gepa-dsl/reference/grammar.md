# GEPA 문서 DSL 문법 (normative)

경상북도경제진흥원 문서(사업계획서·공고문·보도자료)를 생성하기 위한 마크다운 변형 문법입니다.
파서는 `lib/docmodel/dsl/parser.ts` 이며, 이 문서가 문법의 정본입니다. 작성자(에이전트)는 **아래 규칙만** 사용합니다.
파서는 절대 실패하지 않습니다: 모르는 구문은 일반 문단으로 처리하고 경고(`warnings[{line, message}]`)를 남깁니다.

```
문서 = front-matter(YAML) + 본문
```

---

## 0. 작성자를 위한 10줄 요약

1. 맨 앞에 `---` … `---` YAML front-matter. `family: plan | notice | press` 필수.
2. `# 제목` = 장(사업계획서: Ⅰ Ⅱ Ⅲ 밴드 / 공고문: `N. 제목` 섹션 바). 번호는 **자동**. 공고문은 3번부터 시작(1·2는 자동 합성).
3. `## 제목` = 절 칩(사업계획서). 라벨 자동(1, 2, 3) 또는 `## 󰊱 제목`, `## [사업개요] 제목`.
4. 본문 줄은 **첫 글자 기호**로 역할 결정: `□` → `ㅇ` → `-` → `·`, 주석 `※`, 각주 `*`. **들여쓰기(공백)는 세지 않아도 됩니다** (파서가 무시하고 가족별 표준 들여쓰기 적용).
5. 기호 없는 줄 = 일반 문단(보도자료 본문). 줄마다 문단 하나. 빈 줄은 세로 여백(의미 있음, 연속 빈 줄은 하나로 합침).
6. 인라인: `**굵게**`, `{red}…{/red}`, `{blue}…{/blue}`, `{color:#rrggbb}…{/color}`, `[텍스트](url)`, `<http://…>`, 줄 끝 `\` = 같은 문단에서 줄바꿈.
7. 표 = GFM 파이프 표. 바로 윗줄에 `{table role=budget widths=… }` 속성 가능. `^` = 위 셀과 병합, `<` = 왼쪽 셀과 병합, `<br>` = 셀 안 줄바꿈. 첫 셀이 `합계`/`계`/`합 계` 이면 합계 행.
8. 펜스: ```` ```box ```` (목적 박스), ```` ```flow ```` (절차도), ```` ```image logo ````, ```` ```attach ```` (붙임), ```` ```toc ````, ```` ```infobox ````.
9. 고정 문구는 **반드시 매크로**: `{{boilerplate:참여제한대상}}` 등. 직접 타이핑하거나 바꿔 쓰지 마세요.
10. `<pagebreak>` = 쪽 나눔, `<조직도>` = 주요업무보고 조직도 자리, `(단위: 천원)` 한 줄 = 표 단위 캡션(우측 정렬).

## 1. Front-matter

- 문서 첫 줄부터 `---` 로 시작하고 `---` 로 닫습니다. 사이는 YAML.
- `family` 키가 가족을 정하고, 가족별 메타 스키마(`NoticeMetaSchema` / `PlanMetaSchema` / `PressMetaSchema`, `lib/docmodel/schema.ts`)로 검증합니다.
- 숫자로 보이는 값(`공고번호: 2026070000`, `연도: 2026`)은 문자열로 자동 변환됩니다. **앞자리가 0인 값은 따옴표**로 감싸세요 (`공고번호: "0012"`).
- **값에 쉼표가 있으면 따옴표**로 감싸세요. 특히 `{ 라벨: …, 값: … }` 흐름형 매핑 안에서 쉼표는 항목 구분자입니다.
  - 잘못됨: `- { 라벨: 사업내용, 값: 홍보물 제작, 마케팅 지원 }` → 값이 `홍보물 제작` 에서 잘리고 경고 발생
  - 올바름: `- { 라벨: 사업내용, 값: "홍보물 제작, 마케팅 지원" }`
- 스키마에 없는 키는 경고, 필수 키 누락·형식 오류는 `severity: "error"` 경고. 이 경우에도 DocModel은 생성되지만(빈 값으로 채운 placeholder 메타) 파이프라인은 오류로 취급해야 합니다.

### 1.2 사업계획서(plan) 메타

`제목`(필수), `부제`, `연도`, `부서`, `등록번호`, `결재: { 담당, 팀장, 실장, 본부장, 원장, 등록일자, 결재일자, 공개구분, 협조 }`,
`요약: { 사업개요, 추진일정, 기대효과 }`(선택, 있으면 표지 다음에 요약 칩 3개 합성), `numbering: roman | arabic`(기본 roman),
`lineSpacing`(기본 160), `body1Font: humanMyeongjoBold | hyHeadlineBold`,
`ladder: gepa | gov`(기본 gov = 행정업무운영 편람 2타 사다리 □0/ㅇ2/-4/·6; gepa = 참고 문서 관행 □1/ㅇ2/-3/·4), `결재.라인`(결재란 직위 5개, 기본 `[담당, 팀장, 실장, 본부장, 원장]`), `house: gepa | bumpis`(기본 gepa; `bumpis` = 범정부오피스·행안부 표준 보고서 서식 — □ HY헤드라인M 16, ○ 휴먼명조 15, ※/* 맑은 고딕 12, 아래 여백 10mm, 연파랑 표 머리글, 번호 칩 절 제목, 연보라 제목 상자).

### 1.3 보도자료(press) 메타

`기관`(기본 `(재)경상북도경제진흥원`), `배포일`(필수), `보도시점`(기본 `즉시`), `담당부서` `담당자` `연락처`(필수), `책임자`(선택, 머리표 작성자 첫 줄 — 예 `실장 남상범`), `이메일`, `제목`(필수), `부제`, `사진`(기본 false), `붙임: [ … ]`.

출력 디자인(docs/design-system/press.md): 머리표 표(GEPA 로고 · 보도자료 로고타입 · 【배포일】 · 담당부서/작성자/연락처) → 파란 괘선 제목 상자(제목 18pt B·`- 부제 -` 16pt B, 장평 100%/자간 0% 기본, 한 줄 초과 시 장평 90%·자간 −20% 한계까지 자동 축소) → 함초롬바탕 15pt 180% 본문. 글자 수: 제목 26자 이하 권장·36자 최대, 부제 30자 이하 권장·42자 최대(공백 포함). **연속된 `□`/`ㅇ`/`-` 줄은 회색(#F2F2F2) 상자 안의 `• ` 항목(14pt)으로 묶여** 출력된다.

## 2. 본문 규칙 (규칙 번호는 `docs/architecture.md` B.2 와 동일)

### 규칙 2 — `#` 장 제목

| family | 결과 | 번호 |
|---|---|---|
| plan | `chapterBand { numeral, title }` | 자동 Ⅰ Ⅱ Ⅲ … (`numbering: arabic` 이면 1 2 3). `# Ⅲ 제목`, `# Ⅲ. 제목`, `# 3. 제목` 처럼 번호를 쓰면 그 번호로 설정되고 이후 자동 번호가 이어집니다. |
| notice | `sectionBar { number, title }` | 자동 **3부터** (1. 모집개요, 2. 지원절차는 메타에서 합성). `# 3. 사업목적` 처럼 명시해도 됩니다. |
| press | 허용 안 함 | 굵은 본문 문단으로 강등 + 경고 |

```markdown
# 추진배경 및 목적        ← plan: Ⅰ 추진배경 및 목적
# 3. 사업목적             ← notice: 3. 사업목적
# 사업기간                ← notice: 4. 사업기간 (자동)
```

### 규칙 3 — `##` 절 제목

- plan → `sectionChip { label, title }`. 라벨은 장마다 1부터 자동. 직접 지정: `## 󰊱 수출매뉴얼 지원`(기호 한 글자), `## [사업개요] 제목`(대괄호 안이 라벨), `## 2. 제목`(숫자).
- notice → 굵은 `□` 문단 (`□ **제목**` 과 동일).
- press → 굵은 본문 문단 + 경고. `###` 이하는 어느 가족이든 굵은 문단 + 경고.

### 규칙 4 — 기호 줄 (본문 사다리)

| 기호 | role | 비고 |
|---|---|---|
| `□` `■` | body1 | |
| `ㅇ` `○` `◦` `❍` `✔` | body2 | `ㅇ` 은 한글 자모(U+3147) |
| `-` | body3 | **뒤에 공백 필수** (`-4%` 는 문단, `---` 도 문단) |
| `·` `∙` `▪` | body4 | |
| `※` | note | |
| `*` | footnote | **뒤에 공백 필수** (`**굵게**` 와 구분) |
| `❖` `◇` `❶` `❷` `❸` `❹` | plain (기호 유지) | 열거용 |

- 줄 앞 공백·탭·전각 공백은 무시. 기호 뒤 공백은 있어도 없어도 됩니다.
- 같은 기호가 연달아 오면(`○○○ 원장`, `□□`) 기호가 아니라 **텍스트**입니다(가명 처리).
- 닮은꼴 기호는 정규화하고 경고: `•` `ㆍ` `‧` → `·`, `–` `—` → `-`, `ㅁ` → `□`, `＊` → `*`, 소문자 `o ` → `ㅇ`.

```markdown
□ **(지원대상)** 안동시 소재 사업장을 둔 중소기업으로 아래 요건을 충족하는 기업
ㅇ 「중소기업기본법」상의 중소기업으로 공장등록증을 보유하고 신청일 현재 가동 중인 기업체
- 가족친화인증기업, 여성기업, 사회적기업
※ 한국표준산업분류 대분류(C)제조업(10~34)에 해당되는 기업
* 건축물관리대장: 공장건축면적이 500㎡ 이하이고 …
```

### 규칙 5 — 기호 없는 줄

`plain` 문단(press 는 `pressBody`). **줄 = 문단**. 연속된 줄은 서로 다른 문단이며 자동으로 이어 붙이지 않습니다(한글 문서는 줄 단위).
`[별첨1] 정량평가 기준` 처럼 `[별첨…]` 으로 시작하면 `attachmentHeading`.

### 규칙 6 — 빈 줄

`blank` 블록. 참고 문서들이 세로 리듬으로 사용하므로 의미가 있습니다. 두 줄 이상 연속 빈 줄은 하나로 합칩니다.

### 규칙 7 — 인라인

| 표기 | 결과 |
|---|---|
| `**굵게**` | bold |
| `{red}…{/red}` `{blue}…{/blue}` | color `#ff0000` / `#0000ff` |
| `{color:#rrggbb}…{/color}` | 임의 색 |
| `[텍스트](http://…)` | link |
| `<http://…>` `<https://…>` `<mailto:…>` | link (텍스트 = 주소) |
| `<br>` | 줄바꿈 (주로 표 셀 안) |
| 줄 끝 `\` | 같은 문단을 다음 줄에 이어 씀(제목 2줄 등). 다음 줄의 기호는 텍스트로 취급 |
| `\x` | 문자 `x` 그대로 (x 가 기호·구두점일 때). `\*\*`, `\{`, `\[`, `\|`, `\<`, `\\` |

- 짝이 안 맞는 `**` 나 `{/red}` 는 문자 그대로 + 경고.
- 굵게와 색은 중첩 가능: `**{red}둘 다{/red}**`.

### 규칙 8 — `<pagebreak>` · `<조직도>`

한 줄에 단독. `pageBreak` 블록.

`<조직도>`(영문 `<orgchart>` 도 같다)는 **주요업무보고 전용**이고 `table { role: "orgChart", rows: [] }`
로 옵니다. 조직도의 글(원장·본부·실·팀·지소)은 참고본 조각
`templates/report/geometry/t09.xml` 에 굳어 있어서 DSL 은 **자리만** 정합니다 —
조직이 개편되면 조각을 다시 뜹니다. 조각이 report 템플릿에만 있으므로 다른 family 에서 쓰면
**파서가 경고하고 블록을 만들지 않습니다**.

### 규칙 9 — `(단위: 천원)`

`(단위: 천원)` 또는 `(단위 : 천원)` 이 **한 줄에 단독**이면 `unitCaption`(우측 정렬 문단). 보통 표(또는 `{table…}` 속성 줄) 바로 위에 둡니다. 표가 뒤따르지 않아도 캡션으로 처리합니다.

### 규칙 10 — 표

```markdown
{table role=budget widths=50.1,86.9,218.7,61.2,61.2}
| 구 분 | < | 산출 내역 | 금액 | 비고 |
|---|---|---|---|---|
| 직접비 | 수출매뉴얼 | 3,000천원 × 15개사 | 45,000 | |
| ^ | 수출직불금 | 1,000천원 × 15개사 | 15,000 | |
| 합계 | < | < | 60,000 | |
```

- 행은 `|` 로 시작. 두 번째 줄 `|---|---|` 구분 행은 있어도 없어도 됩니다(있으면 열 수 기준).
- **첫 행 = 머리글**(`isHeader`, `headerRows: 1`). `header-rows=2` 로 바꿀 수 있습니다.
- `^` = 바로 위 셀과 병합 (위 셀의 `rowSpan` 증가, 이 자리는 `covered: true`). 위 셀이 가로로 병합된 셀이면 그 폭 전체가 덮입니다 — 나머지 자리도 `^` 또는 빈칸으로 두세요.
- `<` = 바로 왼쪽 셀과 병합 (`colSpan` 증가). 첫 열이나 위 행과 병합된 셀 옆에서는 쓸 수 없습니다(문자 그대로 + 경고).
- 첫 셀 텍스트가 `합계` / `계` / `합 계` / `총계` 이면 `isTotal` (머리글 행 제외).
- 셀 안 줄바꿈은 `<br>`, 파이프 문자는 `\|`, 셀 안에서도 `**굵게**` 등 인라인 사용 가능. `∙` `▪` 는 산출내역 셀의 글머리로 그냥 텍스트입니다.
- 열 수가 머리글보다 적으면 빈 셀로 채우고, 많으면 경고.
- **합계 행의 숫자 셀**은 HWPX에서 열 합계 수식 필드(`=SUM(?2:?6)`)가 됩니다 — 표시값이 실제 열 합계와 같을 때만. 한글에서 값을 고치고 수식 갱신을 하면 재계산됩니다.
- **배점 구간 줄**(정량평가표 셀 안): `구분: 30%이상 30 / 30%미만 24 / 20%미만 18 / 10%미만 12 / 5%이하 6` 처럼 `항목 점수`를 `/`로 나열한 줄은 HWPX에서 참조 공고문과 같은 **2×N 배점표(구분/배점 행, 중첩 표)** 로 변환됩니다. `1. 매출액 대비 수출액 비율: 30% 이상 30 / …` 처럼 콜론 앞 문구가 있으면 그 문구는 위 줄로 남고, 콜론 없이 항목이 3개 이상이어도 됩니다. 모든 항목이 숫자로 끝나야 하며, 편집기에서는 한 줄 텍스트로 보입니다.

### 규칙 12 — 고정 문구 매크로 `{{boilerplate:이름 키=값}}`

한 줄에 단독으로 씁니다. 파서가 `lib/docmodel/boilerplate/*.ts` 의 원문을 DSL 줄로 펼친 뒤 일반 규칙으로 해석하므로 **문장을 고치거나 직접 타이핑할 수 없습니다** (`기업게좌` 오타 포함 원문 보존).

| 매크로 | 펼침 |
|---|---|
| `{{boilerplate:참여제한대상}}` | `□ **(참여제한대상)**` + `◦` 7개 항목 |
| `{{boilerplate:일정변경}}` | `※ 상기 일정은 추진 상황에 따라 변경될 수 있음` (공고문 2절은 자동 합성됨) |
| `{{boilerplate:예산상황}}` | `※ 예산상황에 따라 선정기업은 변동될 수 있음` |
| `{{boilerplate:기업부담금}}` | `※ 최대 지원한도에 따라 기업부담금 증가할 수 있음` |
| `{{boilerplate:지급방법 이메일=…}}` | `□ **지원금 지급 방법**` + `ㅇ` 3개 (기업게좌 문장 포함). `이메일` 인자는 받지만 사용하지 않음 |
| `{{boilerplate:기타유의사항 주관기관=안동시}}` | 9절 전체 `ㅇ` 6개. `www.gepa.kr` 은 링크 |
| `{{boilerplate:이의제기}}` | `○ 본 공고와 관련하여 이의사항이 있는 경우에는 … 의견을 제시할 수 있음` |
| `{{boilerplate:정산문구}}` | `※ 예산은 사업 진행 상황에 따라 항목 간 변경 가능하며, 정산은 관련 규정에 따름` |
| `{{boilerplate:끝}}` | 바로 앞 문단 끝에 `.  끝.` (마침표로 끝나면 `  끝.`) 추가. 앞 문단이 없으면 `끝.` 한 줄 |

인자는 `키=값` 또는 `키="값 값"`. 모르는 매크로 이름은 그 줄을 일반 문단으로 두고 경고합니다.

**기관·시군 공모 변형 `대상=기관`** — 신청 주체가 기업이 아니라 시군·기관인 공고(시군 공모, 기관 공모)에서는 위 고정문구의 기업 표현(기업계좌 송금, 휴업 중인 기업, 기업부담금)이 사실과 다르므로 아래 다섯 매크로에 `대상=기관` 을 붙입니다. 기업 모집 공고에서는 붙이지 않습니다.

| 매크로 | 펼침 |
|---|---|
| `{{boilerplate:참여제한대상 대상=기관}}` | `□ **(참여제한대상)**` + `◦` 4개(중복 지원, 보조금 부정수급 이력, 지방비 미확보, 기타) |
| `{{boilerplate:예산상황 대상=기관}}` | `※ 예산상황에 따라 선정 기관 수 및 기관별 지원 규모는 변동될 수 있음` |
| `{{boilerplate:기업부담금 대상=기관}}` | `※ 최대 지원한도에 따라 선정 기관의 지방비 부담이 증가할 수 있음` |
| `{{boilerplate:지급방법 대상=기관}}` | `□ **사업비 교부 및 정산**` + `ㅇ` 3개(협약 후 도비 교부·지방비 편성, 지방보조금 관리 조례에 따른 집행·정산·반납, 중복 지원 불가) |
| `{{boilerplate:기타유의사항 대상=기관 주관기관=…}}` | 9절 `ㅇ` 6개, `참여 기업은`→`신청 기관은`, `신청인`→`신청 기관` |

### 규칙 13 — 합성 블록 (작성자가 쓰지 않는 부분)

front-matter 검증 후 가족 expander(`lib/docmodel/dsl/expanders/`)가 앞부분을 만듭니다. 블록 id(`b001`, `b002`…)는 이 합성 블록부터 문서 순서대로 매깁니다.

- **notice**: `noticeHeader` → `infoBox`(접수방법/문의/선정결과 통보, 이의제기 고정문 포함) → `pageBreak` → `image logo` → `sectionBar 1 모집개요` → `overviewTable` → `sectionBar 2 지원절차` → `procedureFlow` → `note ※ 상기 일정은 …`. 본문 `#` 은 3부터.
- **plan**: `approvalBlock` → `coverTitle`(제목 [+ 줄바꿈 + 부제]) → (`요약` 있으면) `sectionChip{label:'', title:'사업개요'}` + `coverSummary` 문단, 추진일정, 기대효과 순.
- **press**: `pressHeader` → `pressTitle` → `pressSubtitle`(부제 있을 때).

`toDsl()` 은 이 합성 블록을 다시 쓰지 않습니다(메타에서 재생성).

### 규칙 14 — 스트리밍

`createStreamingParser().push(chunk)` 는 `DslEvent[]` 를 돌려줍니다.

| 이벤트 | 시점 |
|---|---|
| `meta` | front-matter 닫힘 (바로 이어서 합성 블록 `block.commit`) |
| `block.open` | 현재 줄이 문단임이 확실해지면(임시 블록, 다음 id 예약) / 표 첫 행 / 펜스 시작 |
| `text.delta` | 열린 문단 줄에 글자가 더 들어올 때 (원문 그대로) |
| `block.upsert` | 표 행 완료마다, 펜스 내용 줄마다 |
| `block.commit` | 줄바꿈으로 문단 확정, 표/펜스 종료, 단독 블록(빈 줄·쪽나눔·매크로 펼침) |

`{{boilerplate:끝}}` 은 이미 커밋된 앞 문단을 다시 `block.commit` 합니다(같은 id 로 교체). 한 번에 넣든(`parseDsl`) 1글자씩 넣든 최종 DocModel 과 id 는 동일합니다.

## 4. 파서가 보내는 경고 (자주 나오는 것)

| 상황 | 처리 |
|---|---|
| front-matter 없음 / family 없음 | `severity: error`, family=plan 가정 |
| 필수 메타 누락 | `severity: error`, placeholder 메타로 계속 |
| 값에 따옴표 없는 쉼표 (`모집개요[3].제품생산…`) | 알 수 없는 키 경고 + "따옴표로 감싸세요" |
| `#` in press, `###` | 굵은 문단으로 강등 |
| `**` 짝 불일치, `{/red}` 단독 | 문자 그대로 |
| `^` 첫 행, `<` 첫 열, 위 행 병합 셀 옆의 `<` | 문자 그대로 |
| `{table …}` 뒤에 표 없음 | 속성 무시 |
| 모르는 role / 속성 / 펜스 / 매크로 | generic · 무시 · 본문 해석 · 일반 문단 |
| `•` `ㆍ` `–` `ㅁ` 등 닮은 기호 | 정규화 |
| ```` ```image ```` 닫지 않음 | 자동으로 닫고 다음 줄부터 본문 |
