# family 레지스트리 구현 계획

> **에이전트 작업자에게:** 이 계획은 `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`로 한 과제씩 실행한다. 단계는 체크박스(`- [ ]`)로 추적한다.

**목표:** 새 DocModel family를 추가할 때 조용히 오작동하는 분기를 없애고, 누락이 컴파일 오류가 되도록 family 축을 레지스트리로 바꾼다.

**아키텍처:** 계층을 지켜 레지스트리를 둘로 나눈다. `lib/docmodel/families.ts`는 문서 모델 층의 관심사(사다리·제목·제목 처리 방식·끝 표기 요구)를, `lib/hwpx/families.ts`는 작성기 선택을 담는다. docmodel은 hwpx를 import 하지 않는다. 기존 3종의 동작은 한 군데도 바뀌지 않으며, 골든 테스트가 그것을 보증한다.

**기술 스택:** TypeScript, zod, vitest, Next 16.3.5

**스펙:** `docs/specs/2026-09-21-공문서-업무보고서-설계.md` (§5.1)

## 전역 제약

- 기존 3종(`notice`·`plan`·`press`)의 출력은 **바이트 단위로 불변**이어야 한다. `pnpm golden`이 판정한다.
- `lib/docmodel/**`는 `lib/hwpx/**`를 import 하지 않는다(단방향 의존).
- 레지스트리는 반드시 `Record<Family, …>` 타입이어야 한다. 그래야 항목 누락이 컴파일 오류가 된다.
- 모든 과제는 `pnpm test && pnpm typecheck && pnpm lint` 통과 후 커밋한다.
- 커밋 메시지는 한글 한 줄 요약 + 필요 시 `- ` 불릿. 끝에 `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.
- `lib/agents/**` 를 고치면 dev 서버를 재시작해야 한다(이 계획에는 해당 없음).

## 사전 조사 결과 — 실제로 위험한 분기는 3곳이다

/**
 * family별 문서 모델 층 사실을 한 곳에 모은 레지스트리.
 *
 * 새 family를 추가할 때 여기에 항목을 빠뜨리면 `Record<Family, DocFamilyDef>` 때문에
 * 컴파일이 실패한다. 예전에는 `family === "notice" ? … : family === "plan" ? … : PRESS`
 * 같은 삼항 연쇄여서, 새 family가 보도자료 설정을 조용히 물려받았다.
 *
 * hwpx 층(작성기 선택)은 lib/hwpx/families.ts 에 따로 둔다 — docmodel 은 hwpx 를 import 하지 않는다.
 */
import type { Family } from "./schema";

export interface DocFamilyDef {
  /** 사람이 읽는 이름 (UI·로그·오류 메시지) */
  label: string;
  /** 글머리 기호 → 앞 반각 공백 타수. 참고 문서 관행 사다리("gepa"). */
  indent: Record<string, number>;
  /**
   * ※ / * 참고가 바로 위 항목(ㅇ ○ ◦ -)에 딸릴 때의 들여쓰기.
   * undefined 면 보정하지 않는다.
   */
  noteIndentUnderItem?: number;
}

export const DOC_FAMILIES: Record<Family, DocFamilyDef> = {
  notice: {
    label: "공고문",
    indent: { "□": 0, "ㅇ": 1, "○": 1, "◦": 1, "-": 3, "·": 4, "※": 2, "*": 1 },
    noteIndentUnderItem: 4,
  },
  plan: {
    label: "사업계획서",
    indent: { "□": 1, "ㅇ": 2, "○": 2, "◦": 2, "-": 3, "·": 4, "※": 1, "*": 2 },
    noteIndentUnderItem: 3,
  },
  press: {
    label: "보도자료",
    indent: { "□": 0, "ㅇ": 1, "○": 1, "◦": 1, "-": 3, "·": 4, "※": 2, "*": 2 },

- [ ] **단계 4: `indent.ts`가 레지스트리를 읽게 한다**

`lib/docmodel/indent.ts` 에서 `NOTICE`·`PLAN`·`PRESS` 상수 세 줄(7-9행)을 지우고, import 와 두 함수를 다음으로 바꾼다.
`GOV` 상수와 `glyphRole` 은 그대로 둔다 — `GOV` 는 family가 아니라 사다리이고, `glyphRole` 은 family와 무관하다.

```ts
import type { Family, Glyph, ParaRole } from "./schema";
import { DOC_FAMILIES } from "./families";

// (GOV 상수는 그대로)

export function leadingSpaces(family: Family, glyph: Glyph | undefined, role: ParaRole, ladder: Ladder = "gepa"): number {
  if (!glyph || glyph === "none") return role === "greeting" ? 2 : 0;
  const t = ladder === "gov" ? GOV : DOC_FAMILIES[family].indent;
  return t[glyph] ?? 0;
}

/** Indent of a ※/* note that annotates the previous item (편람: 딸린 항목의 내용 첫 글자 위치). */
export function noteIndentUnder(family: Family, prevGlyph: string | undefined, ladder: Ladder = "gepa"): number | undefined {
  if (!prevGlyph) return undefined;
  if (ladder === "gov") return (GOV[prevGlyph] ?? 0) + 2;
  if (prevGlyph === "ㅇ" || prevGlyph === "○" || prevGlyph === "◦" || prevGlyph === "-") return DOC_FAMILIES[family].noteIndentUnderItem;
  return undefined;
}
```

 * STAGE_FAMILY 를 진실의 출처로 삼는다. 단계 이름을 손으로 나열하면 새 단계가 조용히 빠지고,

 */
export function isDocStage(stage: string): boolean {
  return STAGE_FAMILY[stage as Stage] !== undefined;
}
