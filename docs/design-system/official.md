# GEPA 공문서 DESIGN SYSTEM — 별지 제1호 일반기안문(행정안전부 시행규칙)

Source: `templates/official/reference.hwpx` (Hancom Office 2022 저장, `curate-template.ts official --from-hwpx`로 큐레이션).
`render-diff exit 0`(무손실). 골격은 다른 세 가족(공고문·계획서·보도자료)보다 훨씬 가볍다 — 공문서는
가변부가 수신·제목·본문·붙임 넷뿐인 **고정 틀**이기 때문이다.

Units: 1 pt = 100 HWPUNIT, 1 mm = 283.465 HWPUNIT (notice.md/press.md와 동일).

수치가 작은 이유: 공고문은 매 섹션 다른 표·강조가 필요하지만, 공문서는 두문·본문·결문 세 덩어리가
전부이고 그 안의 서체 변주가 거의 없다.

## 2. 문서 골격 (paragraph 순서, `templates/official/geometry/index.json`)
| 문단 | 내용 | paraPr |
|---|---|---|
| 0 (`t00.xml`) | 두문 표 6×4 — **첫 본문 문단이 이 문단 안에 같이 들어간다**(별도 문단이 아니다) | 28 |
| 1–6 | 본문 (항목 `paraPr 27 / charPr 8`, 마지막 줄 앞에 오는 붙임 줄은 `paraPr 29 / charPr 8`) | 27 / 29 |
| 7 (`t01.xml`) | 결문 표 11×50 | 12 |

**첫 본문 문단이 두문 앵커 문단 안에 있다**는 것이 이 가족의 핵심 특이점이다. 표 run 다음에 본문 run이
바로 이어지므로, 별도 문단으로 내면 두문 표 아래에 접히지 않는 빈 줄이 하나 생긴다
(`lib/hwpx/writers/official.ts`의 `headTable()`이 이 접합을 수행한다 — 표본마다 문단 id가 다르므로
paraPr는 **언제나 우리 템플릿의 앵커 값**을 쓰고 다른 표본에서 읽은 번호를 옮기지 않는다).

## 3. 문단 속성 (paraPr 27 / 28 / 29)
| paraPr | 줄간격 | 문단 앞/뒤 여백 | 쓰임 |
|---|---|---|---|
| 27 | 180% | (기본) 다음 문단 여백 0 | 본문 일반 항목 |
| 28 | **200%** | **다음 문단 여백 500** | 두문 앵커 문단(표+첫 본문 문단). 다음 항목 앞의 빈 줄 노릇을 이 여백이 대신하므로 빈 문단을 따로 넣지 않는다 |
| 29 | 180% | **앞 문단 여백 1000** | 붙임 줄 — 본문 마지막 항목과 붙임 사이를 띄운다 |

본문 charPr 8 = 대비값 굴림체 12pt 장평 95%(참고: `official.ts`의 `BODY_CHAR`). style-map 역할이 없을
때만 쓰는 대비값이고, 실제로는 참고 문서의 charPr 8을 그대로 읽는다.

## 4. 두문(t00) 셀 지도
6행×4열. 값이 들어가는 칸만 표에 남긴다(나머지는 서식 프레임):
| 셀 (행,열) | 라벨/값 |
|---|---|
| (1,2) | 기관명 |
| (3,0) / (3,1) | `수 신` 라벨 / 값 |
| (4,0) / (4,1) | `(경유)` 라벨 / 값 |
| (5,0) / (5,1) | `제 목` 라벨 / 값 |

수신 칸 값: 수신유형=`내부결재`→`내부결재`, `수신자참조`→`수신자 참조`(목록은 결문에), `수신자`→
그 값 그대로(예: `경영기획실장(경영지원팀장)`).

## 5. 결문(t01) 셀 지도
11행×50열. 결재란 칸은 `이름` 속성이 `직위.1`…`직위.10`으로 붙어 있다(3행이 1~5번째, 4행이
6~10번째 — 결재선이 다섯 명을 넘는 문서를 위한 둘째 줄. 우리 구현은 3행 다섯 칸만 쓴다).
| 셀 (행,열) | 내용 |
|---|---|
| (0,10) | 발신명의 |
| (1,0) / (1,5) | 수신자 라벨 / 수신자 목록(`수신유형=수신자참조`일 때만 채운다) |
| (3,0) (3,9) (3,20) (3,32) (3,42) | 결재란 직위 5칸 (`직위.1`…`직위.5`) |
| (5,0) / (5,4) | 협조자 라벨 / 값 |
| (7,0) (7,3) (7,15) (7,16) (7,24) (7,26) (7,43) (7,48) | `시행` / `처리과-` / `(` / `시행일` / `)` / `접수` / `(` / `)` |
| (8,0) (8,1) (8,7) (8,27) (8,30) | `우` / 우편번호 / 주소 / (빈칸) / 홈페이지 |
| (9,0) (9,2) (9,11) (9,13) (9,22) (9,23) (9,38) (9,39) | `전화` / 번호 / (빈칸) / `전송` / 번호 / (빈칸) / `이메일` / 번호 (빈칸) / 공개구분 |

참고 문서의 결재란은 세 칸만 채워져 있고(`★과장`) 나머지 두 칸이 비어 있다 — 이는 서식이 세 칸이라서가
아니라 **그 문서가 실장 전결**(전결자 서명란에 `전결`을 적고 그 뒤 서명하지 않는 사람의 칸은 두지 않는다,
`gov-manual.md` §1)이었기 때문이다. 다섯 칸 모두 같은 borderFill/paraPr/charPr을 쓴다.

## 6. gov-manual.md 규정 연결
| 이 문서의 요소 | gov-manual.md 규정 |
|---|---|
| 시행 칸에 `처리과-`만 쓰고 일련번호는 비움 | 시행 일련번호는 전자결재가 기안 후 채번한다 — 별지 서식은 빈 칸을 전제한다(§1 문서등록 표시) |
| 결재란 다섯 칸, 전결 시 뒤 칸을 두지 않음 | §1 결재란 규정 그대로 |
| 공개구분 | §1 공개 구분(정보공개법 제9조제1항) |
| 붙임·`끝.` | §4 (시행규칙 제4조제4·5항) — `attachmentParas()`가 항목이 하나면 번호 없이, 둘 이상이면 `1.`/`2.`로 매기고 마지막 항목 뒤에 `  끝.`을 붙인다 |
| 본문 항목 위계(1.→가.→1)→가)…), 하나뿐이면 기호 생략 | §3 |
| 날짜·시간·금액·쌍점·물결표 | §2, `govLint.ts`/`govNormalize.ts`/`format.ts`가 검사·정규화한다 |
