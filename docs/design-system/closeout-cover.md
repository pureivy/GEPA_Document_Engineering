# GEPA 정산·결과보고 자동작성: 커버 공문 패턴과 ERP 연계 가능성 조사

- 조사일: 2026-10-02 / 대상: `AllAboutGEPA/gepa.db`(문서 10,583건, 결의 3,725행, 원인행위 308행)
- 읽기 전용으로 분석했다. 중간 산출물은 `scratchpad/cer/*.json, *.py`에 있다(`core.json`은 분석 표본 457건의 본문과 특징값).

## 0. 핵심 요약

1. **GEPA가 보내는 정산·결과보고 커버 공문은 사실상 "시행 공문(외부)" 하나뿐이다.** 내부결재 공문으로 "정산 및 결과보고"를 올리는 사례는 1건뿐이다. 내부 보고는 **보고서형(등록번호 원페이지)** 으로 하고, 내부결재 공문은 그 뒤 단계인 **반납 지출결의**와 **회계검증 용역 대금 지급**에 쓴다.
2. 표본 457건(외부 시행, 고유 사업 282개, 7개 팀)의 구성은 다음과 같다.
   - (1) 정산+결과(실적): 327건(72%)
   - (2) 정산만: 121건(26%)
   - (3) 결과만: 9건(2%)
   - 수신처는 시군 78%, 도 22%다. 시군 공문은 "반납액" 열과 반납 문구를, 도 공문은 "통장잔액" 열을 쓰는 경향이 뚜렷하다.
3. 정산내역 표는 5열 구조 **(A) 교부액 − (B) 집행액 = (C) 잔액, (D) 이자, (C)+(D) 통장잔액/반납액**가 사실상 표준이다. 차이는 열 이름과 첨자 표기, 재원별 행(도비·시군비, 9%)뿐이다.
4. **ERP로 정산을 재현할 수 있는 조건은 2026년에 집행이 끝난 사업이다.** 2026 본예산 사업 4건을 검증했다.
   - 정산 세부내역 41줄 가운데 38줄(93%)이 금액까지 정확히 일치했다.
   - 나머지 3줄의 원인은 외화 송금 차액 2줄과 여입(−) 누락 1줄이다.
   - 이 차이를 보정하면 총액이 정산보고서 집행액(B)과 원 단위까지 같다.
   - 단, **계약(용역·물품) 지출은 결의내역(resolutions)에 없고 원인행위(commitments.inspected)에만 있다.** 두 테이블을 합쳐야 한다.
5. 반대로 **2026년 정산 커버 공문의 88%는 2023~2025년 사업**이다. ERP 적재 범위(결의일 2026-01-02~2026-09-01)로는 집행액을 재현할 수 없고, 이월분 꼬리와 **반납(잔액·이자) 행만** 잡힌다.
6. ERP에 없는 필드는 지급처(거래처), 실제 지출(이체)일, 지급방법, 계좌, 증빙번호, 건별 내역(1결의가 N건으로 나뉘는 경우), 외화 실지급액, 은행 이자, 여입(−)이다. 정산보고서의 "항목별 세부 집행내역"은 **지급처·지출일 열을 사람이나 다른 원천(통장 거래내역)에서 보충해야** 한다.

## 3. (B) 후속 문서: GEPA(교부기관)가 수행기관에 보내는 정산확정 및 잔액 반납 요청

GEPA가 수행기관(협회·산학융합원·컨소시엄 기업·참여기업)에 보낸 발신 문서는 약 40건이다.

- 정산확정형: 1720, 2023, 1733, 511/515/516, 1503, 1179, 628, 809
- 개별 기업 환수형: 1529~1537, 2125~2131 정착활동비 반납요청, 1568~1592 과지급 반환요청, 8973, 11181

참고로, 도와 시군이 GEPA에 보내는 같은 성격의 문서는 101건을 접수했다(168, 430, 166, 1006~1008 등).

골격(정산확정형 표본 6건 공통):

```
수신 : {수행기관장}  (다수면 "수신자 참조")
제목 : 「{사업명}」 정산확정 및 {집행잔액|이자} 반납 요청        # 변형: "…사업비 잔액 및 이자 반납요청", "…불인정 금액 및 이자 반납 요청"
1. {귀 기관의 무궁한 발전을 기원합니다. | {수행기관 정산보고 공문번호(날짜)}호 관련입니다.}
2. {근거}에 따라 「{사업명}」 정산을 확정하오니, {집행잔액 및 발생이자}를 기한 내 반납하여 주시기 바랍니다.
   근거 예시: 지방자치단체 보조금 관리에 관한 법률 제19조(보조금의 금액 확정), 경상북도 보조금 관리조례 제26조
   가. 사 업 명 (또는 사업개요 묶음)
   나. 반납금액: 금{E}원(금{한글}원)   [- 집행잔액 / - 발생이자 분리]
   다. 정산내역(세부내역) 표: 구분|교부액(예산액)|집행액|집행잔액|발생이자|반납금액
      [불인정형] 반환대상액·불인정 사유·산출내역(불인정+이자)
   라. 반납방법: 계좌이체 ({은행} {계좌}, 예금주 (재)경상북도경제진흥원)
   마. 반납기한: YYYY. M. D.(요일)  (통상 발송 후 1~4주)
   [옵션] 바. 제출서류/행정사항: 반납 영수증·이체확인증 메일 제출
붙임 통장사본(사업자등록증) 1부 | 검증보고서 등.  끝.
```

- 커버 공문(§2)과 달리 **계좌·기한·납부방법이 필수**다. 이 값은 GEPA 사업비 통장 정보 마스터에서 채울 수 있다.
- 교부기관(도)이 GEPA에 보내는 통보는 형식이 다르다.
  - 반납방법이 `별도 고지서 납부`다.
  - `세입과목: 장)세외수입 관)임시적세외수입 항)보조금반환수입 목)시도비보조금등반환수입`, 이자는 `…경상적세외수입 / 이자수입 / 기타이자수입`으로 적는다.
  - `정산결과 검토의견`이 붙는다.
- 확장 시 흐름: ①커버 공문(§2) → ②교부기관 정산확정 통보 접수 → ③반납 지출결의 내부결재(§2.9) → ④ERP `반환금(자체)` 결의. 수행기관을 둔 사업에서는 ①보다 앞서 ⓪ GEPA의 정산확정·반납 요청(§3)이 들어간다. 모든 단계가 같은 5열 표를 재사용한다.

### 4.5 권장 조회 레시피 (SQLite)

입력값:

- `:kw` = 사업 고유 키워드. 사업명에서 연도·「」·"지원사업"을 빼고 짧고 고유한 토큰을 쓴다(예: `캔톤`, `사이공텍스`, `원예 박람회`, `OKTA`, `섬유분야`).
- `:from`, `:to` = 사업기간.

```sql
-- ① 예산사업(biz) 후보: 적요 또는 사업명에 키워드가 나오는 biz (반환금·기본경비 제외)
WITH biz_pick AS (
  SELECT biz, budget_src, COUNT(*) AS n
  FROM resolutions
  WHERE (biz LIKE '%'||:kw||'%' OR summary LIKE '%'||:kw||'%')
    AND biz NOT LIKE '%반환금%' AND biz NOT LIKE '%기본경비%' AND biz NOT LIKE '%인력운영비%'
  GROUP BY biz, budget_src
),
-- ② 집행 라인 = 일반 지출결의 ∪ 계약 지출(원인행위 검수액)
exec_lines AS (
  SELECT 'R' AS src, r.resol_date AS dt, r.biz, r.budget_src, r.budget_item,
         r.amount AS amt, r.summary, r.resol_no AS ref, r.paid
  FROM resolutions r JOIN biz_pick b ON r.biz = b.biz AND r.budget_src = b.budget_src
  WHERE r.status = '결재완료'
    AND r.summary NOT LIKE '%반납%' AND r.summary NOT LIKE '%잡수입%'      -- 이월사업 잔액반납 행 제외
    AND (r.resol_date BETWEEN :from AND :to OR r.resol_date = '')
    -- biz 하나에 행사가 여럿이면(예: 113-19 사이공텍스+이스탄불) 아래 조건을 켠다
    -- AND (r.summary LIKE '%'||:kw||'%' OR r.resol_type = '여비')
  UNION ALL
  SELECT 'C', NULL, c.biz, c.budget_src, c.budget_item,
         c.inspected, c.summary, c.contract_no, NULL
  FROM commitments c JOIN biz_pick b ON c.biz = b.biz AND c.budget_src = b.budget_src
  WHERE c.inspected > 0
),
-- ③ 반납 실적(정산표 C·D 검증용)
refunds AS (
  SELECT resol_date AS dt, amount AS amt, summary,
         CASE WHEN summary LIKE '%이자%' THEN 'D_이자' ELSE 'C_잔액' END AS kind
  FROM resolutions
  WHERE summary LIKE '%'||:kw||'%'
    AND (biz LIKE '%반환금%' OR summary LIKE '%집행잔액 반납%' OR summary LIKE '%잔액 반납%')
)
-- ④-a 세부내역(정산보고서 '항목별 세부 집행내역' 초안)
SELECT src, dt, budget_item, amt, summary, ref FROM exec_lines ORDER BY COALESCE(dt,'9999'), src;
-- ④-b 비목별 집계(정산보고서 '집행 현황' 표)
-- SELECT budget_item, SUM(amt) FROM exec_lines GROUP BY budget_item;
-- ④-c 총괄 검증: B = SUM(exec_lines.amt) ; C·D 실적 = SUM(refunds.amt) GROUP BY kind
```

구현 메모:

1. 비목 매핑은 `budget_item`을 `722-(\d+)\s*([^-]+)-\s*\[\]\s*(.+)` 정규식으로 분해한 뒤 §4.4 표를 적용한다.
2. 적요의 `「사업명」` 접두를 제거해 "세부내역" 열을 만든다.
3. 산출 결과에 다음 경고 플래그를 붙인다.
   - `src='C'`: 지출일 없음
   - 대행수수료: 지급처 = 진흥원으로 자동 채움
   - 국외 송금(적요에 `해외 송금`이나 외화 거래처): 실지급액 확인 필요
4. 이자(D)와 여입(−)은 통장 거래내역에서 입력받는다. ERP 반환금 행은 사후 검증에만 쓴다.
5. 적재 개선을 권한다(AllAboutGEPA 변경 사항, 이번 조사 범위 밖).
   - commitments에 `원인행위일자`·`세부사업` 컬럼을 추가한다.
   - resolutions에 `원인일자`·`분개유형명`을 추가한다.
   - 반환금 결의를 사업 단위로 연결하는 키를 만든다(적요의 「」 추출).

### 4.6 결론과 자동작성 설계 시사점

- **2026년 이후 사업**: ERP만으로 정산표 (B), 비목별 집행현황, 세부내역의 금액·비목·내역 열을 자동 생성할 수 있다. 지출일·지급처·지급방법은 통장 거래내역(정산 붙임으로 이미 존재) 파싱이나 사람 입력이 필요하다.
- **현재 정산 시즌의 대다수(2025 이전 사업)**: ERP로는 (C)·(D) 반납 검증만 가능하다. 커버 공문은 정산보고서 첨부(hwp/pdf/xlsx 773개, 텍스트 추출 99%)에서 A·B·C·D를 읽어 채우는 편이 현실적이다. 정산보고서 첨부의 82%에 일자 열, 56%에 일자별·세부 집행내역이 있다.
- 커버 공문 자체는 §2.10 골격 하나로 457건 대부분을 표현할 수 있다. 필요한 슬롯은 A·B·C·D·E, 사업명·기간·내용, 수신처, 결과보고서 여부, 반납형 여부, 재원별 행 여부다.
