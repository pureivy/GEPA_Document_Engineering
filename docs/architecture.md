### B.2 DSL grammar (`lib/docmodel/dsl/grammar.md`)

The DSL is Markdown-flavoured but parsed by our own line-oriented parser (not a markdown library), so leading spaces and Korean glyph lines survive. Rules:

1. Document = YAML front-matter (`---` … `---`) + body. `family` is required in front-matter.
2. `# ` heading → family L1: plan → `chapterBand` (numeral auto-assigned as Ⅰ, Ⅱ… unless the line starts with a numeral), notice → `sectionBar` (number auto-assigned; `# 3. 사업목적` also accepted), press → not allowed (press body has no bars; use plain paragraphs).
3. `## ` heading → plan `sectionChip` (label auto `1,2,3` or given: `## 󰊱 수출매뉴얼 지원`, `## [사업개요] …`). Notice: bold `body1` label line.
4. Body lines by first non-space glyph: `□`→body1, `ㅇ`/`○`/`◦`→body2, `-`→body3, `·`→body4, `※`→note, `*`→footnote. **Leading spaces in the DSL are ignored**; the canonical indent per family is applied by `indent.ts` (notice: □0 ㅇ1 -3 ※2 *4; plan: □1 ㅇ2 -3 ·4 ※1). The writer agent never has to count spaces.
5. A line without a glyph → `plain` paragraph (or `pressBody` in press). Consecutive non-blank lines without glyph are **separate** paragraphs (no soft wrapping), because 한글 paragraphs are line-based.
6. Blank line → `blank` block (they matter: the reference documents use them as vertical rhythm). Two or more consecutive blanks collapse to one.
7. Inline: `**bold**`, `{color:#0000ff}…{/color}` (shorthands `{blue}…{/blue}`, `{red}…{/red}`), `<http://…>` or `[text](url)` → link, `\` at end of line → `br` (continue the same paragraph on a new line, like 제목 2줄).
8. `<pagebreak>` on its own line → `pageBreak`.
9. `(단위: 천원)` or `(단위 : 천원)` alone on a line immediately before a table → `unitCaption` (right-aligned).
10. GFM pipe table → `table`. Optional attribute line directly above: `{table role=budget widths=131.6,66,251.4,33 header-fill=#e5e5e5 padding=tight font=11}`. Merges inside cells: `^` = merge with the cell above (rowSpan), `<` = merge with the cell on the left (colSpan). A row whose first cell text is `합계`/`계`/`합 계` gets `isTotal` (fill `#d9d9d9` unless overridden). Cell text may contain `<br>` for in-cell line breaks and `∙`/`▪` bullet lines.
11. Fenced directive blocks (` ```name ` … ` ``` `):
   - ` ```box ` (plan 목적 박스 → `summaryBox`; first char ❖/◇ optional)
   - ` ```infobox ` (notice 안내박스, only if meta.접수 is absent; normally synthesized)
   - ` ```flow ` (`단계 | 일정` per line → `procedureFlow`) — notice section 2 is synthesized from meta, but plan 추진절차 may use this too
   - ` ```image logo ` / ` ```image chevron ` / ` ```image <asset-id> width=92.3mm `
   - ` ```attach ` (붙임 list → `attachmentList`, ends with `끝.`)
   - ` ```toc ` (plan 목차 lines)
12. Macros expanded by the parser from `boilerplate/*.ts`, so fixed text cannot be paraphrased by the model:
   `{{boilerplate:참여제한대상}}`, `{{boilerplate:일정변경}}`, `{{boilerplate:예산상황}}`, `{{boilerplate:기업부담금}}`, `{{boilerplate:지급방법 이메일=…}}`, `{{boilerplate:기타유의사항 주관기관=안동시}}`, `{{boilerplate:이의제기}}`, `{{boilerplate:정산문구}}`, `{{boilerplate:끝}}`.
13. Synthesized blocks: after front-matter validation, the family expander prepends/inserts fixed blocks:
   - notice: `noticeHeader` (공고번호/제목/인사말/날짜/기관장) → `infoBox` (from meta.접수) → `pageBreak` → `image logo` → `sectionBar 1. 모집개요` → `overviewTable` → `sectionBar 2. 지원절차` → `procedureFlow` → `note 상기 일정은…`. Body `#` headings then continue numbering from 3.
   - plan: `approvalBlock` → `coverTitle` → optional 요약 chips → body.
   - press: `pressHeader` → `pressTitle`/`pressSubtitle` → body.
14. Streaming: the parser is fed text chunks; a block is "open" until a terminating condition (blank line, next glyph line, fence close, table end). Open paragraphs emit `text.delta`; closing emits `block.commit`. Tables emit `block.upsert` per completed row.

## C. HWPX writer design (`lib/hwpx`)

### C.1 Package assembly (`build.ts`)

`buildHwpx(doc: DocModel): Promise<{ bytes: Uint8Array; report: BuildReport }>`

1. `loadTemplate(doc.family)` reads `templates/<family>/…` once (cached): `header.xml` string, `content.hpf`, `version.xml`, `settings.xml`, META-INF files, BinData map, `fragments/*.xml`, `style-map.json`, `geometry/*.json`.
2. `new StyleRegistry(header, styleMap)` — resolves roles to ids, and can append new `hh:charPr` / `hh:paraPr` / `hh:borderFill` entries when a requested signature is not catalogued (see C.4). It returns the possibly patched header string at the end.
3. `writers/<family>.ts` walks `doc.blocks` and produces the `hs:sec` body string via `emit/*`.
4. Section root: copy the exact `<hs:sec xmlns:…>` opening tag from the template (all 15 namespace declarations), then paragraphs, then `</hs:sec>`.
5. First paragraph: first `hp:run` = `fragments/secPr.xml` + `fragments/colPr.xml` (copied verbatim from the template's paragraph 0); the paragraph's own runs follow; `fragments/pageNum.xml` is placed as a `hp:ctrl` in the first text run (as in the reference).
6. Zip (`zip.ts`, fflate): entry order `mimetype` (level 0, first), `version.xml`, `Contents/header.xml`, `Contents/section0.xml`, `Preview/PrvText.txt`, `Preview/PrvImage.png`, `settings.xml`, `META-INF/container.rdf`, `BinData/*`, `Contents/content.hpf`, `META-INF/container.xml`, `META-INF/manifest.xml`. `META-INF/rhwp-hwp5-origin` is never written.
7. `content.hpf`: template copy with `opf:title` set to `meta.제목/사업명`, `CreatedDate`/`ModifiedDate` set, manifest items kept (image1/image2), plus any extra assets (press photos, v2).
8. `preview.ts`: `PrvText.txt` = first 1,000 characters of plain text (real, not stub). `PrvImage.png` = page 0 SVG rasterized via `@resvg/resvg-js` at ~ 200 px wide if available; otherwise the 68-byte stub (documented as acceptable).
9. `report`: counts (paragraphs, tables, pics), appended style entries, warnings (e.g., unmapped role fell back to `plain`).

### C.2 Paragraph / run emission (`emit/paragraph.ts`, `emit/run.ts`, `lineseg.ts`)

```
<hp:p id="{n}" paraPrIDRef="{paraPr}" styleIDRef="0" pageBreak="{0|1}" columnBreak="0" merged="0">
  <hp:run charPrIDRef="{charPr}"> <hp:t>{escaped text}</hp:t> </hp:run>   (one run per Inline; bold/color/size/font variants resolve to different charPr ids)
  <hp:linesegarray><hp:lineseg textpos="0" vertpos="0" vertsize="{h}" textheight="{h}" baseline="{round(0.85h)}" spacing="{round(h*(ls-100)/100)}" horzpos="0" horzsize="{avail}" flags="393216"/></hp:linesegarray>
</hp:p>
```
- `styleIDRef` is always `0` (바탕글) — the references never use named styles.
- Leading spaces are literal characters in the first `hp:t` (from `indent.ts`).
- `hp:t` escaping: `& < >` plus `"`; `\r` is dropped; `hp:lineBreak` element for `br`; empty paragraphs still get `<hp:run charPrIDRef=…><hp:t></hp:t></hp:run>` (reference does this).
- `pageBreak="1"` on the paragraph that starts the new page (the `pageBreak` block sets a flag consumed by the next emitted paragraph; a `pageBreak` block at the end of the document emits an empty paragraph with the flag).
- **linesegarray policy**: emit exactly one approximate `hp:lineseg` per paragraph, computed as above (`h` = charPr height from the registry, `ls` = paraPr line-spacing %, `avail` = 48188 for body paragraphs or `cellWidth − marginL − marginR` inside cells; for a paragraph hosting an inline table/picture use `vertsize = object height`, matching the reference). Both rhwp writers emit placeholders of this shape, so the rhwp loader accepts it. M1 includes an A/B check (omitted vs approximate) through `@rhwp/core` and one manual Hancom open; the default stays "approximate" unless Hancom rejects it, in which case the fallback is to round-trip the built file through `@rhwp/core` (`new HwpDocument(bytes).exportHwpx()`), which recomputes real segments.

### C.3 Tables (`emit/table.ts`, `emit/cell.ts`)

Two paths:

**(a) Geometry replay** (all house composites): `templates/<family>/geometry/<name>.json` is a frozen snapshot of a reference table extracted by `scripts/extract-geometry.ts`:
```json
{ "name": "overview", "tbl": { "attrs": { "textWrap":"TOP_AND_BOTTOM","textFlow":"BOTH_SIDES","pageBreak":"CELL","repeatHeader":"1","cellSpacing":"0","borderFillIDRef":"4","noAdjust":"0" },
    "sz": { "width": 48341 }, "pos": { "treatAsChar":"1", "...": "verbatim" }, "outMargin": {…}, "inMargin": { "left":510,"right":510,"top":141,"bottom":141 } },
  "cols": [2284, 13321, 1303, 31433],
  "rows": [ { "height": 2355, "cells": [ { "col":0, "borderFill":15, "paraPr":22, "charPr":13, "text":"○", "vertAlign":"CENTER" }, … ] }, … ],
  "prototypes": { "row": 1, "spacer": 8, "last": 10 } }
```
The writer replays attrs verbatim, substitutes cell texts, and clones prototype rows to reach the requested row count (e.g., 모집개요표 with 12 label rows; 절차도 with 4 stages = clone stage+arrow column pair, recompute widths so the sum stays 48144). Table height = Σ row heights; `hp:sz height` recomputed; row heights of cloned rows copied from the prototype.

**(b) Generic tables** (DocModel `table` blocks): built from `TableStyle` + `widthsPt`:
- `hp:tbl` attrs: `id` random 32-bit, `zOrder` incremental, `numberingType="TABLE"`, `textWrap="TOP_AND_BOTTOM"`, `textFlow="BOTH_SIDES"`, `pageBreak="CELL"`, `repeatHeader="1"`, `rowCnt`, `colCnt`, `cellSpacing="0"`, `borderFillIDRef` = registry `borderFill('grid012')`.
- `hp:sz width` = Σ cols (default: scale `widthsPt` so Σ = 48190; if absent, equal split), `hp:pos treatAsChar="1" … horzAlign="LEFT"`, `outMargin` 0 (283 all round for `text` padding boxes), `inMargin` 141 (tight) or 510/510/141/141 (text).
- Rows: `hp:tr` → cells `hp:tc name="" header="0" hasMargin="0" protect="0" editable="0" dirty="0" borderFillIDRef="{bf}"` → `hp:subList … vertAlign="CENTER"` → paragraphs (each with its own lineseg, `horzsize = cellWidth − margins`) → `hp:cellAddr colAddr rowAddr` → `hp:cellSpan` → `hp:cellSz width height` → `hp:cellMargin`.
- Merges: the parser turns `^`/`<` into `rowSpan`/`colSpan` on the anchor and marks covered cells; the emitter skips covered cells, and the anchor's `cellSz.width` = Σ spanned column widths, `height` = Σ spanned row heights.
- Row height: `heightPt` if given, otherwise `max(charHeight×lineSpacing×lines) + margins`, minimum 2355 for 13pt rows / 1800 for 10–11pt rows (values taken from references).
- Cell `borderFill`: resolved by signature `{fill, l,r,t,b}` through the registry, so header rows (`#d9d9d9`, `#dfe6f7`, `#e5e5e5`), total rows, `#3a3c84` evaluation borders, `#808080` grey rules, `none` outer sides, and `0.4/0.5 mm` top rules all become catalogued or appended borderFills.
- Cell paragraphs: `paraPr` by `align` (center/both/left/right/distribute) × line spacing (130/150/160) and `charPr` by `{font: table(맑은 고딕), pt, bold}`; header cells bold.
- Nested tables (정량평가 sub-tables): the DocModel keeps the flat `구분: 30%이상 30 / …` line; `emitTable` synthesizes the reference's 2×N nested 배점표 from it at write time (2026-09-15, `parseScoreLine`/`scoreTable` in writers/common.ts). The editor shows the flat line.

## D. Agent design

### D.1 Runner abstraction (`lib/agents/runner.ts`)

```ts
interface RunSpec { runId: string; sessionId: string; resumeSessionId?: string; cwd: string; addDirs: string[];
                    systemPromptAppend: string; prompt: string; allowedTools: string[]; model?: string;
                    maxTurns: number; maxBudgetUsd: number; wallTimeoutMs: number; idleTimeoutMs: number; jsonSchema?: object; env?: Record<string,string> }
interface AgentRunner { run(spec: RunSpec, signal: AbortSignal): AsyncIterable<AgentEvent>; }
type AgentEvent =
  | { type: 'init'; sessionId: string; model: string; tools: string[]; agents?: string[] }
  | { type: 'text.delta'; text: string; parentToolUseId?: string }
  | { type: 'assistant.text'; text: string; parentToolUseId?: string }          // complete text block
  | { type: 'tool.start'; toolUseId: string; name: string; input: unknown; parentToolUseId?: string }
  | { type: 'tool.input.delta'; toolUseId: string; json: string }
  | { type: 'tool.result'; toolUseId: string; content: string; isError: boolean; parentToolUseId?: string }
  | { type: 'subagent.start'; toolUseId: string; agent: string; description: string }   // Task tool_use with subagent_type
  | { type: 'subagent.end'; toolUseId: string }
  | { type: 'thinking'; text: string }
  | { type: 'result'; ok: boolean; costUsd: number; turns: number; durationMs: number; usage: unknown; structured?: unknown; error?: string }
  | { type: 'stderr'; text: string }
```

`ClaudeCliRunner` spawns:
```
claude -p --verbose --output-format stream-json --include-partial-messages \
  --permission-mode bypassPermissions --allowedTools "<list>" \
  --session-id <uuid>  [--resume <uuid>] --model <model> \
  --max-turns <n> --max-budget-usd <usd> \
  --append-system-prompt-file <tmp prompt file> \
  --add-dir <data/projects/<id>> [--json-schema <schema>]
```
with `cwd = repo root` (so `.claude/agents` and `.claude/skills` load), `stdin` = the user prompt (piped, closed), env = process env minus `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT` (nested-session guard) and minus `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX` (subscription-only guard), plus `NO_COLOR=1`. Auth comes solely from the user's `claude login` state in `~/.claude`; `HOME` is inherited unchanged. `--cwd` is not a real flag; cwd is set on `spawn`. Stdout is parsed line-by-line as NDJSON (`streamJson.ts`), stderr captured to `stderr` events and the run log.

stream-json → AgentEvent mapping:

| stream-json line | AgentEvent |
|---|---|
| `{"type":"system","subtype":"init",session_id,model,tools,agents}` | `init` |
| `{"type":"stream_event","event":{"type":"content_block_delta","delta":{"type":"text_delta","text"}}}` | `text.delta` |
| `…delta.type = "input_json_delta"` | `tool.input.delta` |
| `…event.type="content_block_start", content_block.type="tool_use"` | `tool.start` (input filled in from the `assistant` message later) |
| `{"type":"assistant","message":{content:[{type:"text"}]}}` | `assistant.text` (authoritative full text) |
| `assistant` content `tool_use` name `Task` with `subagent_type` | `subagent.start` |
| `{"type":"user","message":{content:[{type:"tool_result",tool_use_id,content,is_error}]}}` | `tool.result` (+ `subagent.end` when the id is a Task) |
| any message with `parent_tool_use_id` | passthrough `parentToolUseId` (activity shown nested under the subagent) |
| `{"type":"result",subtype,is_error,total_cost_usd,num_turns,duration_ms,usage,structured_output}` | `result` |

### D.2 Stage orchestration

The **main process of each run is the writer persona** (system prompt appended), and research is delegated to the `researcher` subagent through the Task tool. This guarantees the document text streams as top-level `text_delta` events (subagent text is not reliably streamed). The document is emitted inside `<<<DOC` / `DOC>>>` markers in the final assistant message; `docExtractor.ts` starts feeding the DSL parser as soon as the opening marker arrives, and on `assistant.text` completion re-parses the full text as the authoritative document (fixes any divergence from chunk boundaries). The writer is also told to save the same DSL to `<workspace>/<stage>/draft.dsl.md` with Write (the server treats the Write input as a fallback stream if markers never appear).

| Stage | Main persona (system prompt) | Subagents (Task) | Tools allowed | Output |
|---|---|---|---|---|
| 조사 (research) | `researcher` prompt: produce `research/notes.md` (structured: 배경·현황·통계·유사사업·법령·예산 근거, each with source URL and date) + `sources.json` | none (may fan out with `Task(researcher)` for 3 sub-questions) | WebSearch, WebFetch, Read, Write, Glob, Grep, Task | notes.md, sources.json (shown live as markdown) |
| 사업계획서 | `plan-writer`: skills `gepa-dsl`, `gepa-plan-design`; input = topic + notes.md | `researcher` for gap-filling (max 3 calls) | Read, Write, Task, WebSearch, WebFetch | DSL → DocModel → HWPX |
| 공고문 | `notice-writer`: skills `gepa-dsl`, `gepa-notice-design`; input = plan DocModel serialized to DSL (`toDsl`) + 접수/담당 info from project settings | none | Read, Write | DSL → HWPX |
| 보도자료 | `press-writer`: skills `gepa-dsl`, `gepa-press-style`; input = notice DSL + plan DSL | none | Read, Write | DSL → HWPX + md + txt |
| 검토 (each stage, automatic) | `reviewer` with `--json-schema` `{issues:[{blockId, severity, message, fix?}], score}`; checks design-system compliance (glyph ladder, boilerplate present verbatim, 모집개요 rows complete, dates consistent, numbers add up in 예산표, `끝.` present) | none | Read | structured issues → shown in UI; "자동 수정" button runs `--resume <session>` with the issue list |

`.claude/agents/*.md` frontmatter: `name`, `description`, `tools`, `model` (researcher: sonnet — the only subagent actually spawned; the writer/reviewer files mirror `STAGE_MODELS`: plan opus, notice/press/review sonnet). The main `claude -p` process is the writer persona for every stage and gets `--model` from `modelFor(stage, override)` in `lib/agents/limits.ts` (per-run override from the run controls → `GEPA_MODEL_<STAGE>` → `GEPA_MODEL` → `STAGE_MODELS`). Body = persona + hard rules. Skills (`.claude/skills/*/SKILL.md`) carry the design systems: `gepa-dsl` (the grammar, the block/role list, and one full example per family), `gepa-plan-design` (canonical outline §4 of the plan report, level spec, table shapes with widths, house idioms such as `(사업기간)` labels and `끝.`), `gepa-notice-design` (the 6-1 skeleton §8 with placeholders, the section sequence, which parts are fixed boilerplate and must be invoked as macros, the 모집개요 row order, tone), `gepa-press-style` (inverted pyramid, 5W1H lead, quote paragraph, 붙임, length 1,200–1,800자), `gepa-research` (source hierarchy: 통계청/KOSIS, 한국무역협회, 경북도·안동시 보도자료, 법령; cite as `(출처, 연도)`). `docs/design-system/*.md` are the full reports; skills reference them with relative paths so the agent can Read them on demand.

Prompt structure (`prompts/<stage>.ts`): (1) task statement with project topic and stage goal, (2) inputs as file paths under the workspace (never inline large documents; the agent Reads them), (3) required output contract (`<<<DOC` block, front-matter fields required, macros to use), (4) quality bar (from skill), (5) limits (no more than N Task calls, no Bash). `CLAUDE.md` at repo root is short and generic (language: Korean, use skills, never invent statistics without a source).

### D.3 Persistence, resume, limits, errors

- `runs` row created before spawn (`status=running`, `sessionId`); every AgentEvent appended to `run_events` (seq, type, payload JSON) and broadcast to SSE subscribers; the browser reconnects with `Last-Event-ID` and replays from the DB.
- DocModel snapshots: the server writes `doc.json` on every `block.commit` (debounced 500 ms) and a `doc_versions` row on run end and on each user save.
- Resume: `runs.sessionId` kept; "이어서 진행/수정 요청" uses `--resume <sessionId>` with a follow-up prompt (e.g., reviewer issues). `--session-id` is generated by the server (uuid v4) so the mapping is known before the process prints `init`.
- Limits (`limits.ts`): defaults research `maxTurns 40 / $2.0 / 15 min`, plan `60 / $4.0 / 25 min`, notice `30 / $2.0 / 15 min`, press `20 / $1.0 / 10 min`, review `10 / $0.5 / 5 min`; idle timeout 180 s without any stdout line → SIGTERM then SIGKILL after 5 s; abort from UI → same. Exceeding → `result.ok=false` with reason; partial document retained.
- Errors: non-zero exit or `is_error` → `runs.status=failed`, error text shown in the activity log; DSL parse errors are non-fatal (line flagged, paragraph falls back to `plain`, listed in the "검토" panel); HWPX build/validation failures block download and show the report.
- Concurrency: one active run per stage; RunManager lives on `globalThis` to survive Next dev HMR; API routes use `export const runtime = 'nodejs'` and `dynamic = 'force-dynamic'`.

## E. Web UI design

Routes: `/` (projects, "새 프로젝트": 주제, 지역/주관기관, 담당 연락처), `/projects/[id]` (PipelineBar: 조사 → 사업계획서 → 공고문 → 보도자료, each card with status/last run/cost/download), `/projects/[id]/[stage]` (StageRunner).

Top `RunControls` (실행/중지/재검토/자동수정, model select, budget shown live) and bottom `DownloadBar` (HWPX 다운로드, PDF via rhwp export-pdf, .md/.txt for press, 버전 기록).

- `HwpEditor`: TipTap with custom nodes mapped 1:1 to DocModel blocks (`nodes/paragraph.ts` with attrs `{role, glyph, blockId, align}`, `chapterBand`, `sectionChip`, `sectionBar`, `summaryBox`, `infoBox` (content `gepaParagraph+`), `overviewTable` (rows editable as label/value cells), `procedureFlow` (stage/when cells), `gepaTable` (extends `@tiptap/extension-table` with attrs `widthsPt/role/style`, cell attrs `fill/colSpan/rowSpan/align`), `image`, `pageBreak`, `unitCaption`, `approvalBlock` (read-only rendering of the grid), `noticeHeader`/`pressHeader` (rendered from meta, meta editable in a side sheet)). Marks: bold, color, link. CSS mimics the page: `.hwp-page { width: 210mm; padding: 12.7mm 20mm; }`, role classes set font family/size/line-height/letter-spacing from `style-map.json` (served as JSON and turned into CSS variables), gradient strip as `linear-gradient(90deg,#47b0bb,#d0eaed)`, chapter band as a 3-cell grid, literal leading spaces preserved with `white-space: pre-wrap`. Page breaks show as a dashed divider; no pagination in the editor (the RenderPane is the paginated truth).
- Typing animation (`TypingController.ts`): a queue consumes parser events; `block.open` inserts an empty node at the right position with a blinking `Caret`; `text.delta` appends characters at a pacing of 6–12 ms/char (`requestAnimationFrame` batches; if the backlog exceeds 400 chars, drain in 40-char chunks so the display never lags the agent by more than ~2 s); `block.upsert` for table rows animates row-by-row; `block.commit` finalizes and autoscrolls (`scrollIntoView({block:'center'})`); editor is `editable=false` while a run is active. Skip-animation button flushes the queue.
- `RenderPane`: after run end (and after every save/export), calls `/export` then `/render?page=n`; shows page thumbnails + selected page SVG (zoom, fit width); status badge shows validation report (contentLoss 0, pages N, appended styles). During a run it shows the last exported render (grey) with "렌더 갱신" that exports the partial DocModel every 20 s (opt-in, since each export costs ~1 s).
- Edit → save flow: TipTap `onUpdate` (debounced 800 ms) → `fromPm(doc)` → zod validate → `PUT /doc` → `doc_versions` row → auto-export → RenderPane refresh. Meta edits via a side sheet form (zod-form from the family meta schema). "원본 DSL 보기" shows `toDsl(doc)`.
- DownloadBar: `GET /download` streams `out.hwpx` with filename `<사업명>_<stage>_<yyyymmdd>.hwpx`; PDF via `rhwp export-pdf --font-path public/fonts`; press `.md/.txt`; history dialog lists versions with restore.

## G. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Font licensing: 휴먼명조/HY헤드라인M/맑은 고딕/굴림 are proprietary (Hancom/HY/Microsoft) and copied from the Hancom bundle | Fonts are copied only by `scripts/setup-fonts.ts` on the developer's machine, `public/fonts/*.ttf` is gitignored, `LICENSE-NOTE.md` states the fonts are for local preview on a licensed Hancom install only; HWPX files never embed fonts (`isEmbedded="0"`); fallbacks `Noto Serif KR` (휴먼명조), `Noto Sans KR 700` (HY헤드라인M/한양중고딕), `Noto Sans KR` (맑은 고딕/돋움) via `@fontsource` are committed so the app works without the copies. 한양중고딕, 돋움, HCI Poppy are not in the bundle and always use fallbacks. |
| Plan template geometry drift (grouped shapes) | The writer never reuses the reference `section0.xml`; only `header.xml` (converted losslessly) and per-table geometry snapshots are reused. The 요약 frame with grouped shapes is re-expressed as plain chip tables. render-diff for plan is page-scoped and informational; Hancom manual open + PNG spot-check is the gate. |
| Hancom acceptance cannot be automated on macOS | Every milestone has an explicit manual Hancom open step; `@rhwp/core` + `rhwp verify` + render-diff are the automated proxies; a "Save-As in Hancom → render-diff against our file" check catches silent normalizations. Keep `HWPX_PLAIN_LINKS` and `--lineseg omit|approx|roundtrip` switches to adapt quickly. |
| linesegarray semantics | Approximate values by default (both rhwp writers do this); fallback = round-trip through `@rhwp/core.exportHwpx()` to get recomputed segments; decision recorded in an ADR after the M1 A/B. |
| Appending to header.xml breaks the "verbatim" guarantee | Append-only, cloned from a catalogued sibling, `itemCnt` maintained, covered by `headerPatch.test.ts` and validated by load/contentLoss; golden documents must build with zero appended styles. |
| claude CLI in a subprocess: auth, permissions, nested-session guard | Uses the user's subscription login (`~/.claude`) and nothing else; env strips `CLAUDECODE*` and all `ANTHROPIC_*` / Bedrock / Vertex vars so a run can never fall back to API-key billing; `--permission-mode bypassPermissions` + explicit `--allowedTools` (no Bash for writers); smoke script in M3 verifies before UI work; a clear UI error if `claude` is missing or logged out (detect `result.is_error` with auth message; show `claude login` hint). |
| Someone later "helpfully" adds an API/SDK path | ADR `0001-cli-only.md` records the constraint; a lint test greps `lib/`, `app/`, `scripts/`, `.env*`, `docs/` for `@anthropic-ai/`, `ANTHROPIC_API_KEY`, `anthropic.messages` and fails CI if found; `package.json` has no Anthropic SDK dependency. |
| Subagent text not streamed / DOC markers missing | Main process is the writer; Write-tool `input_json_delta` fallback; final `assistant.text` re-parse; if neither yields a DOC block the run fails with a visible message and the raw text is kept. |
| Long-running stages, dev-server restarts, SSE drops | Events persisted per line; SSE replay from `Last-Event-ID`; idle/wall timeouts kill orphans; RunManager on `globalThis`; process group kill on abort; `pgrep` cleanup on server start (kills stale `claude -p` runs tagged by our session ids). |
| Cost overruns | Per-stage `--max-budget-usd` and `--max-turns`; live cost in the UI; research capped at 3 Task calls. |
| Model invents statistics | `gepa-research` skill requires a source per number; reviewer flags numbers without `(출처, 연도)`; notes.md carries `sources.json` and the plan-writer may only cite from it. |
| DSL drift by the model (wrong glyphs, spaces, paraphrased boilerplate) | Parser normalizes glyph variants and indents; boilerplate only via macros; reviewer enforces; unknown constructs degrade to `plain` with a warning instead of failing. |
| Nested tables (정량평가) and formula fields | Done in M6: synthesized at write time from the flat score line / total row (see C.3); the editor still shows the flat line. |
| `.claude/` in the repo also loads into the developer's own Claude Code sessions | Acceptable; alternative is `agent/` as the spawn cwd with its own `.claude/` (one-line change in `claudeCliRunner.ts`). |
